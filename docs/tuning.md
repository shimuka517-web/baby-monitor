# 設定の調整

設定は `config/settings.toml` にまとまっています。

```bash
nano ~/baby-monitor/config/settings.toml     # 保存は Ctrl+O → Enter、終了は Ctrl+X
```

- `[alert]` と `[detection]` は**保存すると数秒で自動反映**されます（ログに「設定を再読み込みしました」と出ます）。
- `[camera]` と `[web]` を変えたときは `sudo systemctl restart baby-monitor` で再起動が必要です。
- 書式を間違えると、前の設定のまま動き続け、ログにエラーが出ます。

## 困りごと別の早見表

| 困りごと | 変える項目 | 例 |
|---|---|---|
| 寝返りのたびに通知が来てうるさい | `absent_sec` を長く | 15 → 30 |
| 布団やぬいぐるみに緑の枠が出る（誤検出） | `score_threshold` を上げる | 0.6 → 0.7～0.8 |
| 顔が映っているのに枠が出ない・途切れる | `score_threshold` を下げる | 0.6 → 0.5 |
| 確認中にカウントがすぐリセットされる | `dropout_tolerance_sec` を長く | 2 → 4 |
| 見守り開始までが長い／短い | `confirm_sec` | 10 → 5 |
| 再通知が多すぎる／少なすぎる | `repeat_sec` | 120 → 300 |
| 「まだ顔を確認できていません」が不要 | `waiting_notify_sec` | 600 → 0（無効） |
| 映像が上下逆さま・横向き | `rotate`（要再起動） | 0 → 180 |
| 映像がカクつく・ラズパイが熱い | `width` `height` `detect_width` を下げる（要再起動） | 960 / 540 / 480 |
| 顔が小さく映っていて検出されない | カメラを近づける、または `detect_width` を上げる | 640 → 800 |

## 全項目の説明

### `[alert]` 見守りの判定（自動反映）

| 項目 | 既定 | 説明 |
|---|---|---|
| `confirm_sec` | 10 | 顔がこの秒数続けて見えたら見守りを開始する。それまではアラートを出さない |
| `dropout_tolerance_sec` | 2 | 顔が一瞬消えても、この秒数以内なら「続けて見えている」とみなす |
| `absent_sec` | 15 | 見守り中に顔がこの秒数見えなければアラート |
| `repeat_sec` | 120 | アラート後、見えないままならこの間隔で再通知 |
| `recover_sec` | 3 | アラート後、顔がこの秒数続けて見えたら復帰 |
| `waiting_notify_sec` | 600 | 見守り開始からこの秒数、一度も顔を確認できなければ1回お知らせ。0 で無効 |
| `armed_on_start` | true | 起動時に見守りを開始するか。false なら一時停止で起動 |

### `[detection]` 顔検出（自動反映）

| 項目 | 既定 | 説明 |
|---|---|---|
| `score_threshold` | 0.6 | 顔とみなす確からしさ（0～1）。上げると誤検出が減り見逃しが増える |
| `try_rotations` | true | 横向き（90°）の顔も探す。真上から撮るなら true |
| `detect_width` | 640 | 検出用に縮小する横幅。小さいほど速いが、小さい顔を見逃しやすい |

### `[camera]` カメラ（要再起動）

| 項目 | 既定 | 説明 |
|---|---|---|
| `width` / `height` | 1280 / 720 | 撮影・配信の解像度 |
| `rotate` | 0 | カメラの取り付け向き（0 / 90 / 180 / 270） |

### `[web]` 配信（要再起動）

| 項目 | 既定 | 説明 |
|---|---|---|
| `port` | 8000 | ブラウザで開くポート番号（`http://<IP>:8000/`） |
| `jpeg_quality` | 80 | 配信画質（1～100）。下げると軽くなる |

## 調整のしかたのコツ

- 一度に変えるのは1項目だけにして、変えたら [usage.md](usage.md) の「設置後に必ずやるテスト」で確認してください。
- `score_threshold` は 0.05 ずつ動かすのがおすすめです。
- 見逃しを減らす方向（`absent_sec` を短く、`score_threshold` を下げる）は誤報が増え、誤報を減らす方向は見逃しが増えます。安全側（見逃しを減らす）に寄せるのが基本です。
- 設定を変えたら、変えた内容と理由を `settings.toml` のコメントに書いておくと、他の人が見たときに分かりやすくなります。
