# 仕組みと役割

このシステムがどう動いているか、どのファイル・どの部品が何を担当しているかの説明です。プログラムを直したい人や、挙動の理由を知りたい人向けです。

## 全体の役割分担

| 担当 | 役割 |
|---|---|
| カメラ（Camera Module） | 寝床を撮影する。夜は赤外線ライトの光で撮る（NoIR の場合） |
| Raspberry Pi 4 | すべての処理を1台で行う。外部のクラウドサービスに映像は送らない |
| `baby_monitor.py` | 撮影 → 顔検出 → 見守り判定 → 通知 → ブラウザ配信、を繰り返す |
| `config/settings.toml` | 秒数や感度など、利用者が調整する値 |
| `config/secrets.toml` | 通知先（Discord の URL、Gmail）とブラウザ用パスワード |
| Discord / Gmail | アラートの受け取り。スマホに通知が届く |
| `milk.py` ＋ `web/milk.html` | ミルクの記録。ラズパイ内に保存し、スプレッドシートへ送る（[milk.md](milk.md)） |
| Googleスプレッドシート（`gas/milk_sheet.gs`） | ミルクの記録の共有先。家族やAI（Muse など）が見る |
| 別室のブラウザ | ライブ映像と状態の表示、「見守り開始／一時停止」の操作 |
| systemd（`install-service.sh` が登録） | 電源投入時の自動起動と、異常終了したときの自動再起動 |

アラートで外部に出ていくのは「通知文とその瞬間の写真1枚」だけです。ライブ映像は家の中のネットワークにだけ流れます。ミルクの記録は、設定した場合だけ自分のスプレッドシートに送られます（日時・量・種類・記録した場所）。

## 1フレームごとの処理の流れ

`baby_monitor.py` の `main()` は、次の処理を1秒に数回～十数回繰り返します。

1. **設定の確認**：2秒に1回、`settings.toml` が保存し直されていないかを見て、変わっていれば `[alert]` と `[detection]` を読み直す（`Config.maybe_reload`）。
2. **撮影**：カメラから1枚取得し、`rotate` の設定に合わせて回転する。
3. **顔検出**：検出用に縮小（`detect_width`）して、OpenCV の YuNet で顔を探す（`FaceDetector`）。正面で見つからなければ、画像を左右に90°回転させて横向きの顔も探す（`try_rotations`）。真上から撮ると顔が横向きに映りやすいためです。
4. **見守り判定**：「顔が見えたかどうか」と時刻を `Monitor.update` に渡し、状態を進める。カメラに依存しない部分なので、`tests/test_monitor.py` で単体テストできる。
5. **描画**：顔の位置に枠（見えている＝緑、見えない＝最後の位置に赤）、日時、状態を書き込む。枠は位置をなめらかにしてちらつきを抑える（`smooth_box`）。
6. **配信**：JPEG にしてブラウザ配信用に置き換える。
7. **通知**：判定で発生したイベント（アラート・復帰など）に応じて Discord / Gmail に送る。送信は別スレッドで行い、通信が遅くても映像や判定が止まらないようにしている。

## 見守りの状態（状態遷移）

| 状態 | 意味 | 次の状態へ移る条件 |
|---|---|---|
| `PAUSED` 一時停止中 | 何もしない | ブラウザで「見守り開始」→ `WAITING` |
| `WAITING` 顔の確認待ち | 顔を確認するまで待つ。**この間は通知しない** | 顔が `confirm_sec`（10秒）続けて見えた → `WATCHING` |
| `WATCHING` 見守り中 | 顔を見守っている | 顔が `absent_sec`（15秒）続けて見えない → `ALERT`（通知） |
| `ALERT` アラート中 | 通知済み。`repeat_sec`（2分）ごとに再通知 | 顔が `recover_sec`（3秒）続けて見えた → `WATCHING`（復帰を通知） |

どの状態でも「一時停止」を押すと `PAUSED` に、「見守り開始」を押すと `WAITING` に移ります。

### なぜこういう作りなのか（設計の理由）

- **確認待ち（`WAITING`）を設けた理由**：起動した直後や寝かせる前は、そもそも顔が映っていません。ここで通知すると毎回誤報になって通知を無視するようになるため、「一度しっかり顔を確認できてから」見守りを始めます。
- **途切れの許容（`dropout_tolerance_sec`）**：顔検出は、同じ顔でもフレームによって一瞬見失うことがあります。確認中に2秒以内の途切れがあっても、続けて見えているものとして数えます。
- **復帰に3秒かける（`recover_sec`）**：布団の柄やぬいぐるみが一瞬だけ顔と誤検出されることがあります。1フレームで復帰扱いにすると、本当は危ない状態なのにアラートが止まってしまうため、3秒続いたときだけ復帰とします。
- **確認待ちが長いときのお知らせ（`waiting_notify_sec`）**：確認待ちの間は通知しない仕組みなので、寝かせた時点ですでにうつ伏せだった場合、いつまでも見守りが始まりません。これに気づけるよう、10分たっても一度も顔を確認できなければ一度だけお知らせします。
- **異常終了したときの通知**：プログラムが落ちたまま気づかないのが一番危ないため、異常終了時に通知し、systemd が5秒後に自動で再起動します。

## プログラムの中身（`baby_monitor.py` の構成）

| 部分 | 役割 |
|---|---|
| `DEFAULTS` / `SECRET_DEFAULTS` | 設定の既定値。設定ファイルに書かれていない項目はここの値を使う |
| `Config` | 設定ファイルの読み込みと、変更時の自動反映。書式が壊れていたら前の設定のまま動き続ける |
| `notify` / `_send_discord` / `_send_gmail` | 通知の送信。設定されている送信先にだけ送る |
| `FaceDetector` | OpenCV YuNet による顔検出。横向きの顔は画像を回転させて探し、座標を元に戻す |
| `Monitor` | 見守りの状態遷移（上の表）。カメラや画面に依存しない |
| `Handler` / `StreamingServer` / `PAGE` | ブラウザ配信。`/` 画面、`/stream.mjpg` 映像、`/status` 状態、`/snapshot.jpg` 静止画、`/arm` `/disarm` 開始・停止 |
| `draw_overlay` | 枠・日時・状態の描き込み |
| `main` | 上記を組み合わせたメインループ |
| `test_notify` | `--test-notify` で起動したとき、カメラを使わずにテスト通知だけ送る |

## 制限・分かっていること

- 顔検出は「顔らしいものが見えるか」だけを判定します。呼吸・体温・体の動きは見ていません。
- 暗い部屋では、通常のカメラだとほぼ映らず検出できません。NoIR カメラと赤外線ライトが必要です。
- 布団で顔が半分隠れている、髪や帽子で顔の形が分かりにくい、カメラから遠すぎる、などの場合は見逃しや途切れが増えます。設置後のテスト（[usage.md](usage.md)）を必ず行ってください。
- 通知はインターネット（Discord / Gmail）経由です。Wi-Fi やネットが止まっていると届きません。
- ブラウザの「見守り開始／一時停止」の状態は、プログラムを再起動すると `armed_on_start` の設定に戻ります。
